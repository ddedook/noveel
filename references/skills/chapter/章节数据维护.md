# 章节数据维护

写章时除正文外，必须通过 `submitChapterWrite.updateManifest` 同步本章引起的设定变更。目的：防止下一章读者出戏（人突然没了、神器归属错、生物首次出场无档）。

## 必须列入 updateManifest 的变化

| 类型 | domain | 示例 |
|------|--------|------|
| 新出场人物 / 人物档案变化 | `role` | 新配角、主角受伤后状态更新 |
| 关系变化 | `roleRelation` | 结盟、决裂、师徒（写入双向） |
| 人物履历 | `roleTimeline` | 晋升、负伤、重大抉择 |
| 物品流转 | `item` | 获得神器、损毁、转手 |
| 物品履历 | `itemTimeline` | 认主、封印、损毁 |
| 新出场生物 / 生物档案变化 | `creature` | 新异兽、灵植状态变化 |
| 生物履历 | `creatureTimeline` | 驯化、反噬、死亡 |
| 世界节点 | `world` | 新地点、势力易主 |
| 世界线 | `worldTimeline` | 某地战乱、政权更迭 |
| 主时间线 | `timeline` | 冲突、悬念、伏笔、转折 |
| 等级体系 | `level` | 体系/等级规则变化（较少见） |

## 可声明无变更

若本章仅推进剧情、不改动任何设定档案，设置 `noSettingChanges: true` 且 `updates: []`。有 `updates` 时禁止再标 `noSettingChanges`。

## owner 与宿主（易混）

- `item` / `creature` 的 `owner` = 归属主人的**人物名字符串**。
- 附属时间线宿主用 `roleName` / `itemName` / `creatureName`（或对应 `*Id`），不是 owner 字段。
- 主人变更 = 实体 `update{owner}` + 对应 `*Timeline`，缺一不可。

## 各域 payload 必填（不完整会被拒收）

| domain | create / createOrUpdate | update |
|--------|-------------------------|--------|
| `role` / `item` / `creature` | `name` + 非空 `profile`（至少一个有内容的字段） | `id` 或 `name` |
| `roleRelation` | 双方引用（from/to id 或 name）+ `relationType` + 非空 `content` | 双方引用 + `relationType` |
| `roleTimeline` | `roleId`\|`roleName` + `timeLabel` + 整数 `timePoint` + 非空 `content` | 同左 |
| `itemTimeline` | `itemId`\|`itemName` + `timeLabel` + `timePoint` + `content` | 同左 |
| `creatureTimeline` | `creatureId`\|`creatureName` + `timeLabel` + `timePoint` + `content` | 同左 |
| `worldTimeline` | `worldNodeId`\|`worldNodeName` + `timeLabel` + `timePoint` + `content` | 同左 |
| `timeline` | `timeLabel` + `timePoint` + `title` + `content` + `eventType` | `timeLabel` + `timePoint` + `title` + `content` |
| `world` | `name` + `kind` | `id` 或 `name` |
| `level` | `system.name` + 非空 `system.levels` | `id` 或 `system.name` |

## 流程

1. `getOutlineContextForChapter` 读本章合同
2. `findEntitiesByName` + `getEntity` 按需拉相关设定
3. 写正文
4. `submitChapterWrite` 一次提交正文 + 清单

## 禁忌

- 正文出现新人物名却不写入 `role` create/update
- 正文出现新生物名却不写入 `creature` create/update
- 只写正文不调 `submitChapterWrite`
- 用空 query 拉全书索引浪费上下文（应带名称查询）

## Writer 模式（侧栏）

- 草稿经 `submitChapterWrite` **仅内存缓冲**（确认前不建章空壳、不写正文/设定、不审查）；字数越界仍可出草稿并附警告。
- **用户确认后**才 `ensure` 章行 → 审查 → 落库；改稿时在上一稿基础上局部修订，章号 `chapterNo` 保持不变。
- 目标章已有正文时，确认落库将覆盖（界面会提示）。
- 设定清单仍须完整；审查未通过时正文与 manifest 均不落库。
